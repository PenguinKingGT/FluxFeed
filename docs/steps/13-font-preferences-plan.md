# 双字体偏好实施计划

## 背景

FluxFeed 当前通过固定的无衬线与衬线字体栈区分界面和阅读内容，用户只能调整文章正文字号，不能选择字体。对于中文长文阅读，字体偏好差异明显；同时，如果把阅读字体直接应用到整个扩展，按钮、列表和设置项也可能失去原有的信息密度与清晰度。

## 目标

1. 将字体设置拆分为“阅读字体”和“界面字体”，两者可以独立选择。
2. 阅读字体作用于文章标题、正文及正文内部标题；界面字体作用于侧栏、文章列表、按钮、弹窗和设置页。
3. 提供系统衬线、系统无衬线和霞鹜文楷三个选项，并在设置页即时预览。
4. 字体偏好保存在现有全局设置中，旧数据自动回退到默认值。
5. 字体文件完全随扩展本地提供，不依赖外部 CDN 或运行时网络请求。

## 字体策略

| 选项 | 阅读字体 | 界面字体 | 资源策略 |
| --- | --- | --- | --- |
| 系统衬线 | 支持 | 不提供 | 使用本机衬线字体栈 |
| 系统无衬线 | 支持 | 支持 | 使用本机无衬线字体栈 |
| 霞鹜文楷 | 支持 | 支持 | 使用按 Unicode Range 分片的 Lite WebFont |

不同时内置思源宋体和思源黑体。完整 CJK WebFont 会显著增加扩展包体积；系统字体选项已覆盖稳定、清晰的衬线和无衬线需求，霞鹜文楷作为具辨识度的附加选择按实际字符分片加载。

## 实施步骤

1. 扩展 `Settings` 数据模型，新增阅读字体和界面字体字段，并补充默认值。
2. 新增字体注册表与 DOM 应用控制器，通过根节点数据属性切换语义字体变量。
3. 接入霞鹜文楷 Lite WebFont，引用 Regular 400 与 Bold 700 的 Unicode Range 分片，覆盖正文和界面强调字重。
4. 将文章标题和正文切换为专用阅读字体变量；现有 UI 的 sans / serif 角色统一受界面字体控制。
5. 在基础样式中覆盖 Chrome 为扩展页面注入的默认 `body` 字体，避免 Popup 与 Options 回退到系统字体。
6. 重构外观设置区，增加两组可访问的字体选择卡片和即时预览。
7. 补充中、英、日文案，以及旧设置回退、DOM 应用和交互测试。
8. 执行测试、类型检查、lint 和生产构建，并检查构建包字体资源体积。

## 验收标准

- 阅读字体切换不会改变侧栏、文章列表、按钮和设置界面。
- 界面字体切换会统一改变所有界面文字，但不会覆盖文章标题和正文的独立选择。
- 切换设置后无需刷新即可生效，重新打开扩展后仍保持选择。
- 旧版本设置缺少字体字段时，使用系统无衬线界面与系统衬线阅读字体。
- 霞鹜文楷不发起外部请求，未使用的字形分片不会在页面启动时全部加载。
- 霞鹜文楷选中时，界面标题、按钮和列表强调文字不会因缺少粗体字形回退到系统字体；等宽字体只用于代码与快捷键键帽。
- Chrome 注入的扩展页面默认字体不会覆盖界面字体偏好，侧栏、列表、按钮和设置区的真实节点均使用所选字体。
- `pnpm test`、`pnpm compile`、`pnpm lint` 和 `pnpm build` 通过。
