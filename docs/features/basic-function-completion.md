# 基础功能闭环

## 目标

本轮在不引入云端服务和新权限的前提下，让 FluxFeed 已有的订阅、阅读、搜索、设置和数据迁移能力形成可靠闭环。重点解决数据保留语义错误、设置项不生效、多 Feed 页面无法正确选择、OPML 丢失目录以及失败状态被界面忽略的问题。

## 功能要求

### 数据保留

- `retentionDays = 0` 明确表示永久保留，不执行按时间清理。
- `maxArticlesPerFeed` 对每个订阅源生效。
- 超出数量上限时优先保留未读和收藏文章，仅清理最旧的已读且未收藏文章。
- 清理候选选取后，最终删除事务重新检查文章当前状态；期间已完成收藏或取消已读的文章保留，过期清理同时重新核对抓取时间。保护状态变化时允许本轮暂时超出数量上限，不改删其他文章补足名额。

### 阅读与搜索

- 文章 HTML 中链接和图片 URL 的额外引号、空白在安全清洗前规范化；规范化后的地址必须经过协议检查，清洗后不得再改写 URL 而激活危险协议。正常 HTTP(S)、相对链接和既有安全图片格式保持兼容。
- `showUnreadOnly` 控制 Inbox 是否只展示未读文章，默认开启；保留用户已保存的选择，全部文章视图不受影响。
- `markReadOnOpen` 的界面文案与实际行为一致：打开文章时自动标记为已读。
- 搜索覆盖标题、摘要、正文、作者和标签，并忽略大小写与 HTML 标签。
- 单订阅和目录查询不加载无关订阅的正文；全局列表按日期索引筛选、排序和分页。未指定分页上限时保留完整匹配结果，不通过截断列表影响全文搜索和文章导航。
- Feed 页面刷新只刷新当前 Feed；其他视图刷新全部订阅。刷新收尾后重新读取订阅元数据、当前文章筛选结果和未读数，无需切换页面；保留当前搜索、来源及仍在结果中的选中文章，失效选择清空。刷新期间的视图/搜索变化以最新状态为准，旧未读计数响应不得覆盖刷新后的计数。
- 切换到收件箱、全部、收藏或目录视图时清除旧 Feed 筛选；离开目录视图时清除旧目录条件。同一视图内搜索和刷新保留当前来源。
- 快速切换视图或搜索时，仅最新文章查询能更新列表、加载状态和错误，晚返回的旧请求不得覆盖新视图。
- 添加订阅后的列表刷新保留当前视图和筛选，不强制切换到仅未读收件箱。

- 阅读快捷键使用 ← 上一篇、→ 下一篇、Enter 打开原文；M 标记已读、S 收藏、F 专注模式继续可用。
- 原文按钮与快捷键均在新标签页打开并切换过去。点击文章卡片后仍可使用阅读快捷键，切换文章时列表焦点跟随选中项；非当前卡片仍可用 Enter 或空格选中。输入控件、工具按钮、可编辑区域、弹窗和带修饰键的组合不触发阅读快捷键；↑ / ↓ 保持滚动，长按 Enter 不重复打开。

### Feed 发现与后台刷新

- 抓取及整条发现链共用 30 秒总时限；单次响应上限 20 MiB（检查声明长度及实际解压后字节），最多跟随 5 次发现链接，检查自指和跨页面循环。失败不提交文章，单个挂起订阅不再永久占据刷新 worker。
- 超时、体积和发现限制错误在订阅弹窗及 Popup 显示本地化提示；失败结束加载并保留输入以便手动重试，不增加自动重试。

- 添加订阅支持直接 Feed 地址，也支持从网站 HTML 中发现第一个有效的 RSS、Atom 或 JSON Feed 链接；后台发现不依赖浏览器 DOM API，兼容 Chrome MV3 Service Worker。
- 相对地址和 HTML 属性实体正确解析；无效 URL、非 HTTP(S) 协议及注释、脚本、样式、template 中的伪链接不作为订阅候选。网站没有候选时稳定返回失败。
- 页面发现多个 Feed 时，用户可以选择具体 Feed。
- 每个候选 Feed 独立判断是否已经订阅。
- 批量刷新最多同时处理 5 个 Feed。
- 刷新查重在最终写事务中只查询目标订阅的 GUID 索引键，不读取全库文章或已有文章正文；查重与插入原子执行，重叠刷新不会重复入库。
- 首次订阅与刷新共用提交规则，单次响应中的重复 GUID 保留第一条；已存文章的阅读、收藏和摘要状态保持不变。不同订阅可使用相同 GUID，返回的新增数按实际插入计算。
- 刷新结果提交与订阅存在性检查处于同一事务；请求期间订阅或所在目录已删除时，丢弃迟到结果，不产生残余文章或未读数。正常提交同时保存文章与刷新元数据，写入失败整体回滚。
- 后台请求失败时 Store 不得伪造成功状态。单订阅及批量刷新分别返回实际新增数与失败订阅数；部分失败仍保留成功入库的文章，批量等待所有 worker 收尾后报告。阅读器同步成功部分并显示可重试错误；刷新按钮防止重复触发，在失败后结束加载，再次刷新清除旧错误。

### 设置保存

- 同一页面的加载和保存按操作顺序处理；快速修改不同字段或同一字段时，后续成功修改不被旧响应覆盖。
- 普通读取不回写设置；后台在事务中合并最新值与变化字段，包含 AI 的部分字段，不覆盖未修改的偏好。
- 保存成功回传实际保存值；失败保留已确认设置，加载状态能结束，后续修改和重试正常执行。文本框保留输入中的字符和空格，失焦后回到确认值。

### OPML

- 导入时识别一级和二级目录，并将订阅放入对应目录。
- 导出时保留现有目录层级。
- 导入结果展示成功、跳过和失败数量。
- 继续保留仅返回 URL 列表的兼容 API。

### 质量保障

- 单元测试覆盖永久保留、数量上限、全文搜索、并发刷新、多 Feed 选择和 OPML 层级。
- Playwright 启动真实 Chromium 扩展，验证 Options 根页面和 Settings Hash 路由均能渲染。
- Playwright 使用本地 RSS 夹具验证添加订阅、文章入库、阅读操作、搜索、持久化和删除订阅的完整闭环。
- E2E 为每个用例和重试创建独立浏览器资料与本地 HTTP 服务；语言、AI 配置及订阅前置数据由当前用例显式准备，不依赖执行顺序。截图按用例和重试分目录保存，详见 [E2E 运行与隔离说明](../../tests/e2e/README.md)。
- Runtime 消息拒绝统一转换为失败响应，Store 不得因为 Service Worker 重载而永久停留在加载状态。

## 不在本轮范围

- WebDAV、Dropbox 或账号同步。
- 系统通知。
- 自定义浏览器 Commands。
- 复杂关键词过滤规则。
- Chrome Web Store 发布流程。
