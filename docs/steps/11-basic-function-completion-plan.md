# 11 — 基础功能闭环实施计划

## 范围

修复基础功能审计中确认的正确性和体验缺口，保持现有 WXT、React、Dexie、Zustand 架构以及扩展权限不变。

## 实施步骤

1. 修正文章保留策略：永久保留不清理，并按每个 Feed 的数量上限清理最旧的已读未收藏文章。
2. 将 `maxArticlesPerFeed` 与 `showUnreadOnly` 接入设置界面和阅读器默认过滤；校准自动已读文案。
3. 实现可复用的文章全文搜索函数，并由文章 Store 统一调用。
4. 将 Feed 详情页刷新限定为当前 Feed，并把全量刷新改为固定并发工作队列。
5. 为 Feed、Article、Settings Store 补齐失败判断，避免失败后更新本地成功状态。
6. 改造 Popup Feed 发现卡片，使多 Feed 可选择、订阅状态按 URL 独立计算。
7. 扩展 OPML 数据模型，导入导出时保留两级目录，并在设置页显示导入结果。
8. 替换占位 Playwright 测试，使用生产构建启动真实扩展并验证 Options 路由。
9. 补齐单元测试，执行类型检查、Lint、Chrome/Firefox 构建与 E2E。

## 风险控制

- 保留 `parseOPML` 和 `generateOPML(feeds)` 的原有调用方式，新增结构化能力采用兼容参数或新函数。
- 数量清理不删除未读或收藏文章，因此实际总数允许暂时高于设置上限。
- 设置保存失败时回滚到服务端确认前的状态，并暴露错误信息。
- E2E 使用临时浏览器用户目录，不读取或修改用户现有 Chrome 配置。

## 完成标准

- 所有新增行为有自动化测试。
- 原有单元测试无回归。
- 工作区不存在测试生成的未跟踪文件。
- 文档描述与实际设置语义一致。
