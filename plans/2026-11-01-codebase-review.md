## R01：HTML 清洗后重新引入危险 URL

- 定位：[sanitize-html.ts:68](../lib/security/sanitize-html.ts#L68)。DOMPurify 清洗后又去除 URL 两端引号并回写，图片地址有相同处理顺序。
- 影响：不可信文章可能绕过清洗器的 URL 协议检查。已复现输出包含 `href="javascript:..."`；MV3 CSP 能限制部分执行，不代表清洗结果安全，也不能据此直接断言扩展页面可执行脚本。
- 修复方向：在最终安全清洗前完成规范化，或回写前显式校验允许的协议；保留合法带额外引号的 HTTP(S) 地址兼容性。
- 验收：覆盖危险协议、引号、空白变体和正常链接；最终 HTML 不包含被后处理激活的危险 URL；图片地址同样验证。
- 完成记录（2026-11-01）：在 inert template 中规范化链接和图片地址，再由 DOMPurify 清洗并返回 DOM fragment；清洗后只添加阅读元数据，不改写 URL。新增 15 项测试，覆盖危险协议、大小写、控制字符、实体引号、正常链接与图片、空地址；修复前 6 项失败，修复后全部通过。`pnpm test --run`（68 个文件、335 项）、`pnpm compile`、`pnpm lint` 均通过。未修改 Runtime、Manifest 或浏览器集成，本次未运行构建与 E2E。修复与本条完成记录一并提交。

## R02：文章查询及刷新反复加载全库正文

- 定位：[storage-service.ts:175](../lib/db/storage-service.ts#L175)、[refresh-feeds.ts:54](../entrypoints/background/refresh-feeds.ts#L54)。查询先全表 `toArray()`，再筛选、分页；每个订阅刷新都使用该查询获取 GUID。
- 影响：查询少量文章仍读取全库完整正文；刷新 F 个订阅会重复执行 F 次全库读取。大量订阅、长正文及持续累积的未读和收藏文章会放大成本。
- 修复方向：按订阅、目录、日期使用 IndexedDB 索引筛选，合理下推分页；增加只获取目标订阅 GUID 的接口，避免刷新读取无关正文。列表与详情拆分需检查所有调用方，不能直接截断数据导致搜索或导航缺失。
- 验收：保留排序、筛选、分页语义；单订阅查询不加载其他订阅正文；刷新查重不再调用全库文章查询；使用大数据夹具对比查询次数、传输量及耗时。
- 完成记录：待填写验证结果、修复提交。

## R03：Chrome 后台网站地址发现依赖 DOMParser

- 定位：[discover-feed-links.ts:14](../lib/feed/discover-feed-links.ts#L14)、[feed-fetcher.ts:46](../lib/feed/feed-fetcher.ts#L46)、[background.ts:52](../entrypoints/background.ts#L52)。后台直接调用依赖 DOMParser 的 HTML 发现函数。
- 影响：Chrome MV3 Service Worker 没有 DOMParser，输入普通网站地址自动发现 RSS 会失败；直接 Feed 地址不受此错误影响。jsdom 单测提供 DOMParser，不能验证该运行边界。
- 修复方向：使用 Worker 可用的解析方式，或明确的离屏文档边界；优先评估无需新增权限的方案。
- 验收：真实 Chrome 扩展中完成「网站地址 → 发现 Feed → 订阅」，同时覆盖直接 Feed 地址、无订阅链接、相对链接；验证 Firefox 构建和相关行为。
- 依据：[Chrome Service Worker 迁移说明](https://developer.chrome.com/docs/extensions/develop/migrate/to-service-workers)。
- 完成记录：待填写验证结果、修复提交。

- 修复方向：明确请求顺序及合并规则，基于最新状态应用成功的部分更新；防止旧加载响应覆盖较新修改。检查嵌套 AI 设置的更新方式。
- 验收：覆盖不同字段并发、同字段连续修改、响应乱序、加载与保存交错、失败后重试；最终 UI 状态和持久化状态一致。

## R05：后台设置读取、保存存在丢更新

## R06：Feed 请求缺少超时、体积及发现环路限制

- 定位：[feed-fetcher.ts:28](../lib/feed/feed-fetcher.ts#L28)。没有请求期限，无限制读取完整响应，发现 HTML 链接后直接递归。
- 影响：挂起响应占据刷新 worker，大型响应增加内存和解析成本；在可执行 HTML 发现的环境中，自指或循环链接会不断请求。Chrome 的 R03 可能先于环路问题触发。
- 修复方向：为整个发现流程设总时限、响应字节上限、跳数和已访问 URL 集合；错误稳定返回并结束加载，不增加无边界重试。
- 验收：mock 覆盖请求挂起、响应正文挂起、超大响应、自指链接、A→B→A、正常多步发现；失败后可重试，整批刷新可结束。
- 完成记录：待填写验证结果、修复提交。

## R07：并发刷新或响应内重复 GUID 导致重复文章

- 定位：[refresh-feeds.ts:54](../entrypoints/background/refresh-feeds.ts#L54)、[schema.ts:7](../lib/db/schema.ts#L7)。查重与写入分离，每条记录生成随机 ID，`[feedId+guid]` 未设唯一约束；过滤过程不更新已见 GUID 集合。
- 影响：定时刷新与手动刷新重叠可重复入库，单次响应中重复 GUID 也会通过过滤，造成重复列表与未读计数。
- 修复方向：按订阅合并并发刷新，在事务内查重及写入；评估唯一索引及历史重复数据迁移。不同订阅使用相同 GUID 仍应允许。
- 验收：并发刷新同一订阅、响应内重复 GUID 均只保留一篇；不同订阅不误去重；若调整 schema，覆盖旧库迁移并保留已读、收藏等状态。
- 完成记录：待填写验证结果、修复提交。

## R08：刷新结果重新写入已删除订阅的文章

- 定位：[refresh-feeds.ts:46](../entrypoints/background/refresh-feeds.ts#L46)、[storage-service.ts:57](../lib/db/storage-service.ts#L57)。请求期间删除订阅后，返回结果仍直接保存文章，更新不存在的 Feed 不会恢复父记录或报错。
- 影响：留下没有所属订阅的文章，重新出现在收件箱和未读统计中，无法再通过原订阅删除。
- 修复方向：在包含 feeds/articles 的事务中确认订阅存在，再提交刷新结果；已删除则丢弃结果。单纯限制并发无法解决此问题。
- 验收：挂起请求期间删除订阅或所在目录，再释放请求；不得产生残余文章，未读统计正确。
- 完成记录：待填写验证结果、修复提交。

## R09：清理任务可能删除刚被收藏的文章

- 定位：[storage-service.ts:247](../lib/db/storage-service.ts#L247)、[storage-service.ts:262](../lib/db/storage-service.ts#L262)。先读取删除候选，后独立 bulkDelete；候选状态可能在间隔内变化。
- 影响：用户刚收藏或重新设为未读的文章，仍可能被旧候选名单删除，违背未读和收藏文章保留规则。
- 修复方向：最终删除前在 articles 事务内重新检查资格，避免把整个跨订阅计算过程都放进长事务。
- 验收：过期清理和超额清理均覆盖候选选取后发生收藏、取消已读的情况；保护文章保留，仍符合条件的文章正常删除。
- 完成记录：待填写验证结果、修复提交。

## R10：刷新后列表、未读数及错误反馈不同步

- 修复方向：增加阅读器刷新协调流程，成功后更新文章与计数，失败时展示可重试错误；保留当前筛选与有效的选中文章。
- 验收：刷新新增文章后无需切换路由即可看到；未读数更新；失败有提示、加载结束且能重试；覆盖单订阅及全部刷新。

## R11：简报失败后继续分派付费批次

- 定位：[digest-chunker.ts:42](../lib/ai/digest-chunker.ts#L42)、[daily-digest.ts:127](../lib/ai/daily-digest.ts#L127)。Promise.all 提前失败后，其他 worker 未停止领取后续任务。
- 影响：UI 已报告失败，后台仍会继续请求；用户重试可能与遗留批次重叠。实际复现：失败返回时启动批次为 `[0,1]`，稍后变为 `[0,1,2,3]`。
- 修复方向：首个终止性失败阻止领取新任务，等待已开始任务收尾或可靠取消后再结束。保留现有超时、无效响应的降级策略，不混入重试策略调整。
- 验收：失败后不再启动新批次；无遗留拒绝；重试不与未收尾任务重叠；正常路径保持并发上限及结果顺序。
- 完成记录：待填写验证结果、修复提交。

## R12：JSON Feed 纯文本及 Atom XHTML 正文丢失

- 定位：[json-feed.ts:8](../lib/parser/json-feed.ts#L8)、[atom.ts:17](../lib/parser/atom.ts#L17)、[parser-utils.ts:31](../lib/parser/parser-utils.ts#L31)。JSON Feed 忽略 content_text；Atom 通用 readText 只读取对象的 __cdata/#text，忽略 XHTML 嵌套结构。
- 影响：合法条目正文为空，或被摘要替代，阅读和后续 AI 摘要丢失信息；两种情况均已复现。
- 修复方向：JSON Feed 缺少 HTML 时读取纯文本并正确转义、保留换行；Atom 按 text/html/xhtml 分别处理，保持最终清洗边界。
- 验收：覆盖 content_text-only、HTML 优先、纯文本中的 `<`/`&`/换行，以及 Atom 三种正文类型、混合行内元素；确认无重复转义或结构丢失。可拆为 R12a、R12b 两次修复，均完成后才勾选 R12。
- 依据：[JSON Feed 1.1](https://www.jsonfeed.org/version/1.1/)。
